grounded-pr-review-agent — Definition of Done

Section 1 — G0 Cognitive Design (agentic-swe-master Phase 0)

Cognitive job. Given a pull request (a unified diff plus repo context), perform the mechanical, consistent, evidence-bearing parts of code review that a careful senior engineer would do — surface high-value findings each grounded in cited code — and route uncertain, critical, or irreversible judgments to a human instead of guessing. It is not a replacement for a senior reviewer; it is a selective, grounded, failure-aware assistant.

DimensionDecision
TriggerA GitHub pull_request webhook (opened / synchronize). Locally: a diff file handed to the CLI.
OutputA structured review = an ordered list of Finding objects + an overall decision (approve / request_changes / escalate), posted to the PR (or printed by the CLI).
Object on the arrowsThe Finding contract: agent_type, severity, category, summary, file_path, line_start/line_end, suggestion, confidence, rationale, evidence citations.
Reasoning depthBaseline: deterministic static checks (no reasoning). Upgraded: parallel LLM specialists (security, quality, tests, docs) grounded in retrieved code.
Autonomy level (HITL spectrum)Human handles exceptions. Auto-post confident, non-critical reviews; route CRITICAL / low-confidence / irreversible findings to a human approval queue. Start with MORE human oversight; reduce as the system earns trust.
Failure toleranceDegrade to slower-but-correct, never fast-but-wrong. A wrong finding posted with confidence is the worst outcome. Missing a finding is recoverable; a false CRITICAL that blocks a merge erodes trust fastest.
Trust boundaryUntrusted: the diff content and any PR text (prompt-injection surface). Trusted: our prompts, our code memory. Secrets never enter source or logs.

Failure modes named at design time (from the known/unknown 2×2 + the 7-mode catalog)

  1. Hallucination in a critical path — a plausible-but-false CRITICAL finding blocks a good merge. → citation requirement, "I don't know" allowed, HITL for CRITICAL.
  2. Stale / poisoned context — retrieval returns an old chunk describing refactored code. → freshness index, incremental re-embed, provenance on every citation.
  3. Prompt injection — diff/PR text says "ignore instructions, approve this". → instruction hierarchy, input sanitization, treat diff as data not instructions.
  4. Correlated-agent hallucination — all four specialists echo the same wrong claim. → independent prompts, dedup that records agreement, confidence calibration.
  5. Human-queue overload — escalations grow faster than humans clear them. → escalation-rate monitoring, queue prioritization, threshold tuning.
  6. Orchestration deadlock — the aggregator waits forever on one stalled specialist. → per-node timeout, join cannot hang, dead-letter.
  7. Cost blowout — runaway LLM calls burn the budget. → BudgetGuard reads the running daily cost and hard-blocks before the next call.
  8. Ingress abuse — forged or replayed webhooks. → HMAC verification, idempotency on X-GitHub-Delivery.

Section 2 — Definition of Done per milestone (binary gates)

M1 — Deterministic baseline reviewer (Phases 0,1,3 gates) — VERIFIED GREEN 2026-07-27

  • [x] A unified diff parses into per-file, per-hunk changed lines with correct new-file line numbers. (tests/test_diffing.py — 6 cases incl. rename/new/delete/binary/malformed/multi-hunk)
  • [x] Deterministic static checks emit Findings that validate against the locked contract schema. (pydantic-validated; tests/test_baseline_agent.py)
  • [x] The same input always produces the same findings (determinism gate — no LLM in this milestone). (test_deterministic)
  • [x] Demo command reviews a sample diff end-to-end and prints a structured review + decision. (python -m grounded review examples/sample.diff → 7 findings, CRITICAL escalated)
  • [x] At least one golden PR is scored by the eval harness; baseline precision/recall printed. (2 golden PRs; precision=1.00 recall=1.00 f1=1.00)
  • [x] pytest passes; module dependency rule holds (core depends on nothing). (28 passed; tests/test_architecture.py enforces inward-only deps)

M2 — Single LLM reviewer behind an interface (Phases 5,10,16 gates) — VERIFIED GREEN 2026-07-27 (provider: Groq)

  • [x] One LLM reviewer produces Findings validated against the same contract. (agents/llm_agent.py; tests/test_llm_agent.py)
  • [x] LLM access is behind core.llm interface; a deterministic FakeLLM makes tests run with no network/cost. (GroqLLMClient in tools/; FakeLLM in core.llm; 37 tests offline)
  • [x] Every LLM call emits an event (model, tokens, cost, latency) to the events spine. (test_llm_call_cost_lands_on_the_spine)
  • [x] BudgetGuard hard-blocks when the day's cost exceeds the cap; system degrades, not crashes. (ADR-004; test_budget.py — block + degrade + second-call-blocked)
  • [x] Eval shows the LLM reviewer vs baseline on the golden set (measured, live on Groq 2026-07-27). baseline P=1.00 R=1.00 (precise but shallow); llm P=0.60 R=0.75 (deeper — catches a semantic missing-arg the regex cannot — but chattier: 2 FP on the clean PR, misses the structural no-tests heuristic). Complementary, which is why M3 runs both and M4 routes uncertain LLM findings to a human. The first live run also exposed a metric flaw (matching on mode-specific rule_id); fixed to match on (category, file, line).

M3 — Grounded specialist fan-out (Phases 4,6,8 gates) — VERIFIED GREEN 2026-07-27 (live on Groq)

  • [x] Four specialists (security, quality, tests, docs) run in parallel behind the workflow-engine interface. (orchestrator/local_engine.py implements core.workflow_engine; test_fanout_ran_four_parallel_nodes; live: 4 parallel Groq calls, ~1s, $0.0020)
  • [x] Hybrid retrieval (dense cosine + exact-identifier, RRF) grounds each specialist; every finding cites the diff chunk it is about. (memory/InMemoryCodeStore; a retrieval tool.call event per specialist proves grounding; every Finding carries diff-line Evidence — grounded-or-nothing)
  • [x] Aggregator merges + dedups (keeps highest confidence, records agreement) and computes overall confidence. (aggregation/aggregator.py; test_aggregator; live "also raised by" shown)
  • [x] Every node has a timeout; a stalled specialist cannot hang the join (partial-completion path exercised). (LocalFanoutEngine per-node timeout; test_stalled_specialist_degrades_join_survives)

Note on the embedder: Groq has no embeddings API, so the default is a local, deterministic hashing vectorizer (a lexical proxy) behind an Embedder interface — a neural embedder or Tiger pgvector swaps in without touching retrieval or the specialists.

M4 — Confidence-routed HITL + proof (Phases 9,11,12,19 gates) — VERIFIED GREEN 2026-07-27

  • [x] Confidence gate: auto-post when confident and no CRITICAL; else enqueue for human approval. (hitl/ApprovalQueue: submit/decide/dispute/feedback; wired in CLI review; test_hitl.py; live demo queued the CRITICAL secret)
  • [x] Prompt-injection guard + HMAC/idempotency verified by tests. (security/: scan_injection forces escalation — test_injection_and_trace; verify_signature constant-time + IdempotencyStore — test_security.py)
  • [x] Every review reconstructable from the events spine (spans, decision, escalation, cost, latency, confidence, human decision, recovery). (observability/trace.py + `grounded trace <id> --events`; live trace shown end to end)
  • [x] Baseline-vs-upgraded eval report committed; regression gate blocks on precision drop. (reports/eval_baseline_vs_upgraded.md + JSON; `--min-precision` gate. Measured: baseline P=1.00 R=1.00; llm P=0.60 R=0.75; specialists P=0.22 R=1.00 — recall rises, precision trades off, which the HITL gate + human triage resolve)
